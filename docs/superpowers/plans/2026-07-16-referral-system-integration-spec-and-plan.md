# ALOEC Referral System: Technical Specification & Implementation Plan

This is a comprehensive, text-based specification and step-by-step implementation plan designed to be copied directly into coding terminals or LLMs (like OPENCODE TERMINAL). It details the architecture, sequence logic, database models, and the code changes required to implement the ALOEC Referral System.

---

## 1. TECHNICAL SEQUENCE LOGIC

The referral tracking system operates on two paths:

### PATH A: Web Registration (Recommended - 100% Reliable)
1. **User Action:** The invited guest clicks the referral link: `https://aloec.app/?ref=ALOE-JUAN`.
2. **Landing Page Capture:** The Landing Page captures the `?ref=ALOE-JUAN` query parameter via JavaScript and saves it in the browser's `localStorage` as `aloec_ref_code`.
3. **Web Registration:** The guest registers an account directly on the web Landing Page using a simple form connected to Firebase Auth.
4. **Firestore Association:** Upon successful registration, the web registration handler creates a document in the `/users/{new_uid}` collection in Firestore. It retrieves the code `ALOE-JUAN` from `localStorage` and saves it in the user's profile under `referral.referredByCode: "ALOE-JUAN"` and `referral.status: "referred"`.
5. **App Download:** The guest is redirected to download the app from Google Play/App Store.
6. **Mobile Login:** The guest opens the mobile app and logs in using the credentials created on the web.
7. **Attribution Complete:** The mobile app queries `/users/{new_uid}` and reads the existing referral association from Firestore. The user immediately receives their referral discount/benefits.

### PATH B: Clipboard Fallback (Automatic Assistance)
1. **User Action:** The invited guest clicks the referral link: `https://aloec.app/?ref=ALOE-JUAN`.
2. **Landing Page Capture:** The Landing Page captures the `?ref=ALOE-JUAN` query parameter via JavaScript and saves it in the browser's `localStorage`.
3. **Frictionless Download:** The user clicks "Descargar App" directly.
4. **Clipboard Copy:** Before redirecting to the App/Play Store, JavaScript copies the string `ALOE-JUAN` to the system clipboard of the mobile device.
5. **App Store Redirect:** The browser opens the App Store or Google Play Store.
6. **Mobile Install & Open:** The user downloads, installs, and opens the ALOEC mobile app for the first time.
7. **Clipboard Read:** During registration on the mobile app, Flutter reads the clipboard content. If it matches the pattern `ALOE-[A-Z0-9]+`, the app autofills the "Referral Code" field.
8. **Registration:** The guest completes registration. The app writes the new user document to `/users/{new_uid}` with `referral.referredByCode: "ALOE-JUAN"` and `referral.status: "referred"`.

## 2. FIRESTORE DATA MODEL (SCHEMAS)

### Collection 1: `/users/{uid}` (Fields to be added)
Add these fields to the existing user documents:
```typescript
interface UserReferralFields {
  referral: {
    code: string;             // Generated uniquely for each user upon creation (e.g. "ALOE-JUAN123")
    referredByUid?: string;   // Firebase UID of the user who referred them (resolved from code)
    referredByCode?: string;  // Referral code used during sign up
    status: 'none' | 'referred' | 'converted'; // Status of referral conversion
  };
  affiliateBalance: {
    pendingUSD: number;       // Accumulated unpaid commissions (float)
    withdrawnUSD: number;     // Total commissions paid historically (float)
  };
}
```

### Collection 2: `/commissions/{commissionId}` (New Collection)
Records each commission earned by a referrer when their referred user purchases a Premium subscription.
* **Document ID:** Autogenerated by Firestore.
```typescript
interface CommissionDocument {
  id: string;                 // Autogenerated
  referrerUid: string;        // UID of the affiliate receiving the commission
  referredUid: string;        // UID of the customer who purchased the subscription
  referredEmail: string;      // Email of the referred customer
  amountUSD: number;          // Commission amount earned in USD
  percentageApplied: number;  // Affiliate percentage at the time of sale (e.g., 20)
  purchaseId: string;         // ID of the premium purchase/payment record
  status: 'available' | 'withdrawn' | 'cancelled';
  createdAt: timestamp;       // Firestore Timestamp
}
```

### Collection 3: `/payout_requests/{requestId}` (New Collection)
Stores payout withdrawal requests made by users.
* **Document ID:** Autogenerated by Firestore.
```typescript
interface PayoutRequestDocument {
  id: string;                 // Autogenerated
  userUid: string;            // UID of the affiliate making the request
  amountUSD: number;          // Payout amount requested
  paymentMethod: 'paypal' | 'binance' | 'bank_transfer_ec';
  paymentDetails: {
    paypalEmail?: string;     // Required for PayPal
    binanceId?: string;       // Required for Binance Pay
    bankName?: string;        // Ecuador Bank Transfer: e.g., "Banco Pichincha"
    accountType?: 'savings' | 'current'; // Ecuador Bank Transfer: Ahorros/Corriente
    accountNumber?: string;   // Ecuador Bank Transfer
    holderName?: string;      // Ecuador Bank Transfer: Beneficiary name
    holderId?: string;        // Ecuador Bank Transfer: Cédula/RUC of holder
    holderEmail?: string;     // Ecuador Bank Transfer: Beneficiary email
  };
  status: 'pending' | 'approved' | 'rejected';
  rejectionReason?: string;   // Reason if status is 'rejected'
  createdAt: timestamp;       // Request timestamp
  processedAt?: timestamp;    // Payout timestamp
}
```

### Collection 4: `/settings/referrals` (New Configuration Document)
Stores global settings editable only by system admins.
* **Document ID:** `referrals` (Single document under `/settings` collection)
```typescript
interface ReferralSettingsDocument {
  commissionPercentage: number;     // Standard commission rate (e.g. 20)
  minimumPayoutAmountUSD: number;   // Minimum threshold for withdrawal (e.g. 10.00)
  referredDiscountPercentage: number; // Discount rate for the referred user (e.g. 15)
  active: boolean;                  // System master switch
  updatedAt: timestamp;             // Update timestamp
}
```

## 3. STEP-BY-STEP IMPLEMENTATION PLAN

### Task 1: Web Tracking & Clipboard Setup (Landing Page)
1. **Modify `aloec_landing/index.html`:**
   Add URL parameter parser at the bottom of the page. Save the code in `localStorage`:
   ```javascript
   const urlParams = new URLSearchParams(window.location.search);
   const ref = urlParams.get('ref');
   if (ref) {
       localStorage.setItem('aloec_ref_code', ref);
   }
   ```
2. **Implement Download button actions in `aloec_landing/index.html`:**
   Intercept the download link clicks. If `aloec_ref_code` exists, copy it to the clipboard before redirecting:
   ```javascript
   function downloadApp(storeUrl) {
       const code = localStorage.getItem('aloec_ref_code');
       if (code) {
           navigator.clipboard.writeText(code).then(() => {
               // Proceed to redirect to store after copying
               window.location.href = storeUrl;
           }).catch(() => {
               window.location.href = storeUrl;
           });
       } else {
           window.location.href = storeUrl;
       }
   }
   ```

### Task 2: Firebase Security Rules & Backend (Functions)
1. **Add Security Rules in `aloec_backend/firestore.rules`:**
   ```javascript
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       // Users rules
       match /users/{userId} {
         allow read, write: if request.auth != null && request.auth.uid == userId;
       }
       // Commissions rules
       match /commissions/{commissionId} {
         allow read: if request.auth != null && resource.data.referrerUid == request.auth.uid;
         allow write: if false; // Only written via Cloud Functions
       }
       // Payout requests rules
       match /payout_requests/{requestId} {
         allow read, create: if request.auth != null && request.resource.data.userUid == request.auth.uid;
         allow update, delete: if false; // Payout status updated by Admin only
       }
       // Settings rules
       match /settings/referrals {
         allow read: if request.auth != null;
         allow write: if request.auth != null && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
       }
     }
   }
   ```
2. **Create Trigger Cloud Function `onPurchaseCompleted`:**
   Listen to the collection where premium subscription payments are recorded. If a payment succeeds:
   - Load the buyer's user profile: `/users/{buyerUid}`.
   - Check if `referral.referredByUid` exists.
   - If present, read commission parameters from `/settings/referrals`.
   - Calculate commission amount = `purchaseAmount * commissionPercentage / 100`.
   - Create document in `/commissions`:
     ```javascript
     {
       referrerUid: referrerUid,
       referredUid: buyerUid,
       referredEmail: buyerEmail,
       amountUSD: commissionAmount,
       percentageApplied: commissionPercentage,
       purchaseId: purchaseId,
       status: 'available',
       createdAt: admin.firestore.FieldValue.serverTimestamp()
     }
     ```
   - Update Referrer balance in `/users/{referrerUid}`:
     Increment `affiliateBalance.pendingUSD` by `commissionAmount`.
   - Send Push Notification to referrer via FCM:
     "¡Has ganado una comisión! Tu cuenta ha recibido un saldo de $X USD de tu referido."

### Task 3: Mobile Client Integration (Flutter)
1. **Clipboard Reading on First Startup:**
   During registration screen initialization, read the clipboard:
   ```dart
   import 'package:flutter/services.dart';

   Future<void> checkReferralClipboard() async {
     ClipboardData? data = await Clipboard.getData(Clipboard.kTextPlain);
     if (data != null && data.text != null) {
       final text = data.text!.trim();
       // Check matching pattern e.g. ALOE-XXXX
       if (RegExp(r'^ALOE-[A-Z0-9]+$').hasMatch(text)) {
         setState(() {
           referralController.text = text;
         });
       }
     }
   }
   ```
2. **User Registration Integration:**
   When submitting the signup form, pass `referralCode` to the creation method. If a code is provided, the function queries Firestore for a user whose `referral.code == referralCode`. It retrieves their UID and writes the relationship during user document creation:
   ```typescript
   // On signup database write
   {
     uid: newUserUid,
     email: email,
     referral: {
       code: generateUniqueCode(displayName),
       referredByCode: referralCodeUsed,
       referredByUid: foundReferrerUid, // Resolved from referralCodeUsed
       status: 'referred'
     },
     affiliateBalance: { pendingUSD: 0, withdrawnUSD: 0 }
   }
   ```
3. **Referral Dashboard UI:**
   Create screen `/features/referrals/presentation/referral_dashboard_screen.dart` displaying:
   - Shareable Referral Link: `https://aloec.app/?ref=${user.referral.code}` (uses Flutter `share_plus` to send via WhatsApp, social media, etc.).
   - Visual Balance metrics: Pending, Withdrawn.
   - Payout Request Button (disabled if balance < minimumPayoutAmountUSD).
   - History of referred users and history of Payout requests.
4. **Payout Request Form Screen:**
   Create screen `/features/referrals/presentation/payout_settings_screen.dart` with:
   - Method selector dropdown: PayPal, Binance, Bank Transfer (Ecuador).
   - Form fields conditionally rendered per payment method (bank transfer fields validated strictly).
   - Writes to `/payout_requests` collection on submit.

### Task 4: Next.js Admin Panel Integration
1. **Payout Approvals Panel (`aloec_admin/src/pages/admin/payouts/index.tsx`):**
   - Query all documents in `/payout_requests` where `status == 'pending'`.
   - Display a list with the request details.
   - Add buttons for:
     - **Approve Payout:** Opens a modal to confirm the bank/wallet transfer was done. When confirmed, calls a secure HTTPS Cloud Function to debit the pending balance, increment the withdrawn balance, set the payout status to `approved`, and send a success push notification.
     - **Reject Payout:** Opens a modal to enter `rejectionReason`. Updates the request status to `rejected` and sends a failure push notification.
2. **Affiliate Administration Panel (`aloec_admin/src/pages/admin/affiliates/index.tsx`):**
   - List all users with active referral status.
   - Display fields to customize individual referral percentages or disable users from the affiliate program.
   - Edit Global settings (commission rates, minimum withdrawal threshold) in `/settings/referrals`.
